# Changelog

All notable changes to `kmp-forge` will be documented in this file.

Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Versioning: [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed
- **`/kmp-forge-groom` is now `/kmp-forge-refine`**, and the docs, the `kmp-product-owner` agent and the `backlog-issue-authoring` skill say *refine* throughout. The autonomous loop's runbook key `queue-empty-groom` is now `queue-empty-refine`; the loop still reads the old key, and re-running `/kmp-forge-add-autoloop` renames it.

### Fixed
- **Feature template: no dead Back button on the start destination.** `add<Name>Entries(onNavigateBack)` and the generated screen take a nullable `(() -> Unit)?`; the screen shows its Back control only when it is non-null. The app's start destination is wired with `onNavigateBack = null`, because `navigateBack` never pops the root and the button did nothing. Pushed destinations keep `onNavigateBack = navigateBack` (the add-feature wiring is unchanged). `Home.kt`, the add-feature/add-screen recipes and the canonical nav examples in `docs/architecture.md` / `docs/stack.md` (whose start destination had the same bug) say so. kmp-reviewer warns when the start destination gets a non-null back.
- **Feature template: the placeholder no longer looks like shipped UI.** The screen's content branch rendered "`<Name>` ready"; it now renders the `placeholder_content` string ("`<Name>`: replace this placeholder with the real screen content") under a `// TODO(kmp-forge):` marker, so QA and reviewers can tell template from product. kmp-reviewer warns about a feature that still renders it.

## [0.5.0] - 2026-10-09

The first two roles of a spec-driven "software factory": GitHub issues are the one backlog (only a human approves work with `ready`), OpenSpec is the default change workflow with kmp-forge's own rules, a product owner turns ideas and the MVP spec into workable issues, and a QA engineer checks every change's acceptance scenarios — with tagged tests and, on Android, journeys on a device.

**Upgrading a project scaffolded with ≤ 0.4.0** — nothing changes by itself. Supervised projects: `brew upgrade openspec` (≥ 1.14), `openspec init --tools claude` if the project has no `openspec/`, then copy the plugin's `overlay/openspec/config.yaml.tmpl` rules into `openspec/config.yaml`, `overlay/ci/spec-link.yml` into `.github/workflows/`, and the new issue forms; create the labels with `bash <plugin>/scripts/issues.sh labels`. **Autonomous-loop projects must re-run `/kmp-forge-add-autoloop`** (with no loop PR open): it migrates `openspec/backlog.md` to issues (filed without `ready` — you approve them), updates the merge guard to v3 and adds the new runbook keys (`ready-approvers`, `queue-empty-groom`, `qa`, `qa-device`). Until then the loop stops at Phase 0 and points you there.

### Added
- **GitHub issues are the single source of work.** Open issues labeled `ready` are the backlog — for supervised sessions and the autonomous loop alike — and **only a human applies `ready`**. New `scripts/issues.sh`: `labels` creates the workflow labels (`ready`, `in-progress`, `epic`, `priority:high|low`, `no-spec`, `chore`, `adr`; run by init when it creates the GitHub repo, by adopt and add-autoloop), `next` picks the issue to work as code, not model judgment — resume `in-progress` first (or report `paused` if a human paused it, rather than starting a second slice), then `priority:high` → unlabeled → `priority:low`, oldest first, skipping `epic`s, issues blocked by an open **Depends on** / native "blocked by" issue, finished issues someone reopened, and any issue whose author or `ready`-labeler is not the loop's account or a listed approver (issue forms auto-apply labels on an outsider's behalf, so a label alone proves nothing); fork PRs can't rename a change. The bug form gains optional Acceptance criteria / Depends on / Change name (bug slices ship as `fix(…)`). The feature issue form is now the **Feature / backlog item** form (Problem · Acceptance criteria as WHEN/THEN · Out of scope · Depends on · Needs a human first · Change name · Notes); the PR template asks for `Fixes #<issue>`.
- **OpenSpec by default.** `/kmp-forge-init` asks for the spec workflow (OpenSpec recommended, plain docs opt-out), runs `openspec init --tools claude` and installs kmp-forge's project rules as `openspec/config.yaml` (`overlay/openspec/`): context (locked stack, issues as the work source) plus per-artifact rules — the proposal names `Issue: #<n>` and turns its Out of scope into Non-goals, every acceptance criterion becomes a scenario, types land in their layer, every scenario gets a `// Scenario: <name>`-tagged test. Requires OpenSpec ≥ 1.14 (checked by init, add-autoloop and doctor; older CLIs ignore `config.yaml`). The scaffolded CLAUDE.md gets a **Work & spec workflow** section (`SPEC_WORKFLOW`). Adopt offers the same.
- **Product owner: `/kmp-forge-groom` + `kmp-product-owner` agent + `backlog-issue-authoring` skill.** `/kmp-forge-groom <idea | #issues | --gaps>` has the agent read the MVP spec, the current OpenSpec specs and every open/recently closed issue in its own context and draft workable issues — one-PR slices with observable WHEN/THEN acceptance criteria, epics split dependencies-first, outsiders' issues re-filed rather than edited, duplicates dropped, priority suggestions for the queue — then files the drafts you pick and prints the `gh issue edit … --add-label ready` command for you to run. The agent is read-only; every GitHub write happens in the main conversation. The skill holds the issue-writing rules for any session. In the autonomous loop, `queue-empty-groom: on` (new runbook key, install default) has the agent draft up to 3 next slices from MVP-spec gaps when the queue empties; they are filed without `ready`, so nothing is built until you approve it.
- **QA engineer: `kmp-qa` agent.** Verifies an implemented change against its acceptance scenarios: maps every OpenSpec scenario to a test tagged `// Scenario: <name>` (flags missing or hollow ones), and in device mode builds the debug app and runs each user-visible scenario as an Android CLI journey on a device — a running emulator, else a connected physical device (only the app under test is touched; a differently-signed store install is never removed; a locked phone is skipped), else an AVD it boots — through the Android CLI (adb only to list devices and to tap / type), with screenshots at every check, crash / ANR dialogs failing the journey, and background/foreground plus cold-start checks on changed screens (`android run` restarts the process, so "after restart" scenarios are real) — writing `build/qa/<change>/report.md`. Returns PASS / FAIL / ERROR, never edits code, and errors rather than passes when it could not verify. Supervised: ask for it after `/opsx:apply`. Autonomous loop: a third reviewer in the code gate (`qa: device | tests-only | off`, asked at install; `qa-device:` pins a serial or AVD); its blocking findings block the merge, `ERROR` escalates, and the fixer turns a failed journey into a fix plus the tagged test that catches it on the host. `docs/testing.md` § Acceptance documents the convention.
- **`spec-link` CI check** (`overlay/ci/spec-link.yml`) — a `feat:` PR that changes production code must carry its OpenSpec change (anything under `openspec/changes/` or `openspec/specs/` — `/opsx:apply`'s ticked `tasks.md` counts) or the `no-spec` label. Other PR types pass; a no-op without `openspec/`.

### Changed (BREAKING)
- **Autonomous loop: the GitHub-issue queue replaces `openspec/backlog.md`.** `/kmp-forge-next-increment` asks `issues.sh next` for its slice, marks it `in-progress`, names the change `<issue>-<kebab>` (reused across crashes), opens the docs PR with `Refs #<issue>` and the code PR with `Fixes #<issue>`, and closes out the issue instead of ticking a file; deferred findings become one follow-up issue (never `ready`). Workers (`kmp-loop-proposer`, `kmp-loop-implementer`, `kmp-spec-critic`) read the issue themselves. `AUTOLOOP.md`'s `backlog:` key is replaced by `ready-approvers:`; a runbook that still has it makes the loop stop and point at `/kmp-forge-add-autoloop`, which migrates each unchecked backlog item to an issue (filed without `ready` — you approve them) and removes the file. Steering moves to GitHub labels.
- **merge-guard v3** denies applying the `ready` label in `enforce` mode — `gh issue create|edit`, `gh api` label writes, GraphQL label mutations, MCP issue/label tools — from the orchestrator and every subagent, so the loop can never approve its own work. Re-run `/kmp-forge-add-autoloop` to update a project's copy.

## [0.4.0] - 2026-10-08

Scaffolds build again on the current stack, end to end: `/kmp-forge-init` (now downloading straight from kmp.jetbrains.com) and `/kmp-forge-add-feature` produce projects that pass `./gradlew build koverVerify` on Android, iOS, desktop and web; the autonomous loop's merge gate is safe; adopt is non-destructive.

**Upgrading a project scaffolded with ≤ 0.3.2** — existing projects don't change by themselves. Worth patching: `release.yml` (the blank `$RUNNER_TEMP` keystore line, `permissions: contents: write`, injected signing), strings that exist only in `values-en/` (move them to `values/`), the autoloop hook command (re-run `/kmp-forge-add-autoloop` — it detects the old guard version), and the Kover gate (apply `id("kmp-forge.root")` at the root). `/kmp-forge-add-feature` now wires features at the `// kmp-forge:` markers of the `:shared` composition root and falls back to printing the lines when an older host has none.

### Added
- **Autonomous build loop (opt-in), promoted from a battle-tested downstream project.** Three tiers: (1) `driving-ci-green` skill — the canonical watch-checks / read-failures / mirror-CI-locally recipe, active in every project; (2) `kmp-spec-critic` agent — adversarial PASS/REVISE/BLOCK review of an OpenSpec change proposal, usable fully supervised; (3) the full loop — `/kmp-forge-add-autoloop` installs OpenSpec (`openspec init --tools claude`), a backlog + `AUTOLOOP.md` runbook (with a machine-read `## Loop configuration` section), and a 4-mode (`off|log|enforce-ci|enforce`) `merge-guard.sh` PreToolUse hook; `/kmp-forge-next-increment` (wrapped by `/loop`) then runs pop-slice → docs PR → spec gate → code PR → code gate → auto-merge, merging only when CI is green AND the posted 🤖 gate verdict reads PASS. Worker agents `kmp-loop-proposer` / `kmp-loop-implementer` / `kmp-loop-code-reviewer` / `kmp-loop-fixer` keep all heavy context out of the orchestrator, making the loop compaction-proof and crash-resumable. Touched (lockstep): `commands/kmp-forge-add-autoloop.md`, `commands/kmp-forge-next-increment.md`, `agents/kmp-{spec-critic,loop-proposer,loop-implementer,loop-code-reviewer,loop-fixer}.md`, `skills/driving-ci-green/`, `overlay/autoloop/`, `docs/autoloop.md`, `docs/product-workflow.md` (OpenSpec: overkill → opt-in), `docs/ci.md`, `README.md`, `overlay/root/CLAUDE.md.tmpl`, `CLAUDE.md`.

- **`:shared` composition root** (`overlay/shared/`) — `/kmp-forge-init` now renders `App.kt` (`KoinApplication` + `AppTheme`), `AppModules.kt` (the Koin module list), `AppNavigation.kt` (Nav 3 back stack with a `SavedStateConfiguration` registering every route, per-entry ViewModel scoping) and a placeholder `HomeRoute`, replacing kmp.new's sample `App.kt`. Previously nothing created `startKoin`/`NavDisplay` (init.md wrongly said kmp.new did), so the layer modules were never loaded, every `/kmp-forge-add-feature` fell back to "apply manually", and a hand-wired screen crashed with "KoinApplication has not been started". `/kmp-forge-add-feature` / `/kmp-forge-add-screen` wire into the files' `// kmp-forge:` markers.
- **`scripts/kmp-new.sh`** (replaces `kmp-new-url.sh`) — the wizard's form is a plain GET to `kmp.jetbrains.com/generateKmtProject`, so `/kmp-forge-init` now downloads the project directly (`download`, Compose UI on every target, tests included) instead of asking the user to fill the SPA by hand; `url` prints the wizard URL with the targets pre-selected (it reads them from query parameters) as the manual fallback. The old script's "no URL parameter support" premise and its library checkboxes were stale — the wizard has no library picker any more.
- **Toolchain floor: AGP ≥ 9.4.1, Gradle ≥ 9.8.1** — `apply-overlay.sh pin-toolchain <project> [--ios] [--web]` raises the catalog's `agp` and the Gradle wrapper (with the distribution's sha256) without ever downgrading, and raises the build heaps the targets need (`--ios`: Gradle daemon for Kotlin/Native links; `--web`: Kotlin daemon for the js/wasmJs Compose executables). Used by init, adopt (asked first), add-platform and doctor's remediation. `fetch-latest-versions.sh` also reports the latest Gradle release; `/kmp-forge-bump-stack` updates the wrapper the supported way.
- **Kover 75% gate, actually enforced** — new root convention `kmp-forge.root` aggregates every module that applies `kmp-forge.kmp.library` (new features included automatically, `:testing` skipped), excludes what line coverage can't meaningfully measure (`@Composable`, generated resources/serializers, Koin/Nav 3 wiring, routes, platform dispatchers, the Ktor client factory, `:ui` tokens) and fails `koverVerify` below 75%. Previously no template wrote a rule, so the gate passed at 0%, and the `docs/ci.md` snippet didn't compile.
- **`:testing` module** — shared test doubles in `commonMain` (KMP has no `testFixtures`), a `commonTest`-only dependency of `:domain`/`:data`/`:feature-*`. `TestDispatcherProvider(testScheduler)` takes the `runTest` scheduler.
- **Ktor / SQLDelight opt-ins wired by kmp-forge** — init step 6 renders `overlay/optional/ktor/` (`createHttpClient()`, bound in `dataModule`) and adds the per-target engines, or applies the SQLDelight plugin + `AppDatabase` declaration + per-target drivers. Selected libraries used to be silently dropped (the wizard lost its picker) while CLAUDE.md still listed them.
- **Android CLI** — `/kmp-forge-doctor` checks for Google's `android` CLI (install command per host), `docs/testing.md` § Running on a device or emulator documents `android emulator` / `run` / `layout` / `screen` with an emulator-first rule (never install to a physical device without asking), and the scaffolded CLAUDE.md points at it.

### Changed (BREAKING)
- **Locked stack bumped to current stable** — Orbit 9.0.0 → 12.0.1 (9.x `orbit-viewmodel`/`orbit-compose` were Android-only AARs, so features couldn't compile off Android), Koin 4.0.4 → 4.2.2, Coil 3.1.0 → 3.6.3, Ktor 3.1.2 → 3.6.0, Kermit 2.0.5 → 2.2.0, kotlinx-datetime 0.6.2 → 0.8.0 (`Instant`/`Clock` now live in `kotlin.time`), kotlinx-serialization 1.8.1 → 1.11.0, Nav 3 UI 1.1.1 → 1.1.2, DataStore 1.1.7 → 1.2.1, SQLDelight 2.1.0 → 2.4.1, Store 5.1.0-alpha05 → 5.1.0-beta01, Detekt 1.23.7 → 1.23.8, Spotless 7.0.2 → 8.10.3, ktlint 1.5.0 → 1.8.0, Kover 0.9.8 → 0.9.11. Orphaned `koinAndroidx` removed.
- **Orbit 12 API** — templates/docs/agents use `OrbitContainerHost<State, State, Nothing>` + `orbitContainer(...)` (the `ContainerHost` alias and `container(...)` factory are deprecated) and the `testWithInternalState { expectInternalState { … } }` harness (initial state auto-asserted; `test()`/`expectInitialState()`/`expectState` are deprecated). kotlin-result docs use `onOk`/`onErr` with explicit imports (2.x deprecates `onSuccess`/`onFailure`; ktlint rejects the wildcard import the docs prescribed).
- **Feature package segment drops dashes** (`photo-detail` → `…feature.photodetail`, Koin module `photoDetailModule`) — the old `photo_detail` failed ktlint `package-name` and detekt `PackageNaming`.
- **Navigation 3 is ONE artifact** — only the JetBrains Compose Multiplatform port `org.jetbrains.androidx.navigation3:navigation3-ui`, which re-exports the matching Google `navigation3-runtime` as `api` on every platform. The separate `androidx-navigation3-runtime` library and `androidxNavigation3Runtime` version ref are gone (templates, init/adopt wiring, ADR 0004, docs, fetch script).
- **`/kmp-forge-add-platform` rewritten** — it pointed at a `KmpLibraryConventionPlugin.kt` that no longer exists, listed an invalid `android` target, and left iOS as "TBD". It now downloads a reference project with the new platform via `kmp-new.sh` and copies that platform's app module (`iosApp/`, `webApp/`, `desktopApp/`) and `:shared` target blocks; web means `js` + `wasmJs`.
- **Web scaffolds build** — init passes both `js` and `wasmJs` to the overlay modules (kmp.new's `:shared` declares both), drops DataStore from `:data` for web (no `js` variant before 1.3), and the library convention declares `binaries.executable()` for js/wasmJs on Compose modules (Compose UI tests load Skiko from a webpack bundle — CMP-4906).
- Module templates use the wizard's `libs.compose.*` catalog entries and `kotlin { android { } }` instead of the deprecated `compose.*` accessors and `androidLibrary { }`.

### Fixed
- **Catalog additions referenced undeclared version keys** — `kotlinx-coroutines` (and `kotlin`/`agp`/`composeMultiplatform`/`androidx-lifecycle`) were assumed from kmp.new's catalog, but the wizard only emits `kotlinx-coroutines` when Desktop is selected, so an Android+iOS init failed every Gradle invocation with "version reference 'kotlinx.coroutines' doesn't exist". The additions now declare fallbacks for every key they reference; `patch-libs` skips keys the wizard already provides, so the toolchain stays single-sourced.
- **Type-safe project accessors** — module templates and init's `:shared` wiring used `projects.domain`, which current kmp.new no longer enables (`TYPESAFE_PROJECT_ACCESSORS`); every build script failed to compile. Now `project(":domain")`.
- **`Dispatchers.IO` in `:data` commonMain** didn't compile for iOS / shared metadata (and can't for web). `RealDispatcherProvider` now uses an `expect val platformIoDispatcher` with JVM/Android/Native/web actuals; `render-module` maps every source set, not just `commonMain`/`commonTest`.
- **Feature template on the pre-1.0 Nav 3 API** — `EntryProviderBuilder` + a top-level `entry` import → `EntryProviderScope<NavKey>` with the member `entry`. Docs/ADR/agents no longer teach `rememberNavBackStack(Route)` in common code (that overload is Android-only).
- **Feature screen didn't compile and its snackbar never showed** — `Text(state.error)` passed a `DomainError`; errors now map to a string resource. The screen hosts its `SnackbarHost` in a `Scaffold`, so `pendingMessage` is shown and cleared. All template text comes from the feature's own `composeResources/values/strings.xml`.
- **Generated features failed their own gates** — `render-module` created a literal `feature.gallery/` directory (now `feature/gallery/`), the second rename rewrote the directory segment, the TODO comment tripped detekt `ForbiddenComment`, unused params tripped `UnusedParameter`, kebab names produced invalid Kotlin, and the verify task `:feature-x:commonTest` doesn't exist (now `:feature-x:build :shared:build`). `/kmp-forge-add-feature` passes `claude_plugin_root` to the agent.
- **Release workflow never published** — `apply-overlay.sh` ran a bare `envsubst`, which blanked the workflow's own `$ANDROID_KEYSTORE_BASE64`/`$RUNNER_TEMP` (`echo "" | base64 -d > /release.keystore`). Rendering now substitutes only the overlay variables (`OVERLAY_VARS`). `release.yml` also grants `contents: write` to the release job, waits for the ios/desktop jobs, and signs the AAB/APK via AGP's injected signing properties.
- **Spotless 8 build-service clash** — init/adopt apply the new root convention `id("kmp-forge.root")`, so build-logic (and its Spotless/Detekt/Kover) loads in one classloader.
- **Feature strings missing on Android** — under the AGP KMP library plugin a module's `composeResources` are only packaged when `androidResources { enable = true }` is set; the feature template now sets it (verified in the APK's `assets/composeResources/`).
- **iOS framework link OOM** — with the locked stack on the classpath, Kotlin/Native's in-daemon link exhausted kmp.new's 4 GiB Gradle heap on a clean `./gradlew build`; `apply-overlay.sh pin-toolchain --ios` raises `org.gradle.jvmargs` to `-Xmx6144M`.
- **ktlint vs. the Orbit idiom** — `.editorconfig` sets `ktlint_function_signature_body_expression_wrapping = default`, so `fun load() = intent { … }` stays on one line (ktlint_official's `multiline` default wrapped every intent). `/kmp-forge-add-feature` runs `spotlessApply` before building, because ktlint's import order depends on the base package.
- **i18n doc caused crashes on non-English devices** — it put the default strings only in `values-en/`; Compose MP falls back only to the unqualified `values/`. Docs, reviewer and templates now use `values/` as the default table.
- **`fetch-latest-versions.sh`** — its pre-release filter was case-sensitive (reported `2.5.0-Beta1`, `1.12.0-RC`, `0.8.0-0.6.x-compat` as stable), it took the last *deployed* version rather than the highest, it used `tac` (absent on stock macOS — every key came back "not found"), and it emitted toolchain keys no project has (`kotlinGradlePlugin`, …), so `/kmp-forge-bump-stack` never bumped the toolchain. It now version-sorts, accepts only numeric releases (or a pre-release line for pins on one), emits the project's real keys, and adds spotless/ktlint/kover/kotlinResult/store plus the latest Gradle release (`[wrapper]`). build-logic reads ktlint's version from the catalog instead of hard-coding it.
- **`/kmp-forge-adopt` overwrote files it promised to keep** — `.gitleaks.toml`, `build-logic/`, PR/issue templates were copied over existing ones; it never installed the pre-commit hook; it skipped all ADRs when a spec existed; and with any existing workflow it never added the `pr.yml` that `/kmp-forge-add-autoloop` requires. Every copy now goes through a `copy_new` guard (absent → add, present → diff + hand-merge), the hook is installed or chained, ADRs/workflows are handled per file. Also: `git --no-index --no-pager diff` (an invalid option order — every adopt diff errored) → `git --no-pager diff --no-index`.
- **Init lost its variables between Bash calls** — exports don't persist across tool invocations, so a step could render `package .ui` or run `cd ""` (zsh succeeds silently → git ran in the wrong directory). Step 4 now persists them with `typeset -p` to an env file every later block sources and guards with `${VAR:?}`; `render-module` refuses an empty `BASE_PACKAGE`.
- **`.gitleaks.toml` allowlisted `composeApp/…/composeResources` only** — now any `<module>/src/<sourceSet>/composeResources/`, matching the `:shared` + `:feature-*` layout.
- **Merge guard never ran on paths with spaces** — the hook command `${CLAUDE_PROJECT_DIR}/.claude/hooks/merge-guard.sh` was unquoted, so on paths like `…/Personal projects/…` the shell split it, the hook exited 127, and Claude Code treated that as non-blocking. It's now `bash "${CLAUDE_PROJECT_DIR}/.claude/hooks/merge-guard.sh"`, and the installer's smoke check runs the exact wired command under `sh -c`.
- **Merge guard v2 closes the bypasses** — catches `gh pr merge` in any flag order or wrapper, `gh api` merge/ref writes, GraphQL mutations, MCP merge tools, and pushes to main (force, delete, `HEAD:main`, `--all`). PASS now requires the loop account's own `### 🤖` review on the PR's current head commit. In `enforce` it denies subagent merges/pushes, `--admin`, non-bookkeeping pushes to main and subagent edits to the guard; it fails closed on GitHub errors, timeouts (`gh` calls are time-boxed so the hook can't time out open), a missing `jq` and internal errors. Matcher widened to `Bash|Write|Edit|MultiEdit|NotebookEdit|mcp__.*`. Verified with an 80-case suite (bash 3.2 + 5.3, path with a space).
- **The code gate could pass an empty review** — `kmp-loop-code-reviewer` ran `/code-review high --comment` without a target, which reviews the empty local diff of a pushed branch → PASS → auto-merge of unreviewed code. It now runs `/code-review high --comment <pr>`, verifies the PR head and a non-empty `origin/main...origin/feat/<slug>` diff, and returns `ERROR` (escalate) instead of PASS when it can't; `kmp-reviewer` gets the same explicit range and reports an empty scope instead of "no findings".
- **`/kmp-forge-next-increment` resume and precheck** — resumes from PRs looked up by head branch in every state (a crash between merge and backlog tick no longer re-runs a merged slice), checks out the open PR's branch before re-gating, recovers the round from the loop account's reviews and their commits; steering edits (backlog, runbook, guard mode) are committed instead of escalating, the queue-empty archive is committed, the configured kill switch is honored before every phase and merge, and rounds are consistent (`round r/3`, two fix cycles).
- **`/kmp-forge-add-autoloop`** — the origin precondition (`gh -R … repo view`, which always failed) is now `gh repo view <origin url>`; a missing `pr.yml` gets a render command; the kill switch and audit log are gitignored; a re-run updates stale hook wiring.
- **Least-privilege loop agents and a CI-watch race** — the proposer, implementer and code reviewer declare `tools:` (no MCP connectors; the reviewer has no Write/Edit) and workers stage only their own files; `driving-ci-green` waits for checks to register (gh exits 1 with "no checks reported" right after a push) and resolves the failing run id before `gh run view --log-failed`.
- **ADR dates render** — the six shipped ADRs are now `.md.tmpl`, so `Date: ${SCAFFOLD_DATE}` becomes the scaffold date instead of the literal placeholder.
- **git-cliff release notes no longer drop commits silently** — reverts (`revert:` and git's `Revert "…"`) get a **Reverts** group, non-conventional commits land under **Other**, and merge commits are skipped deliberately (documented); lists render tight. `skills/git-cliff-changelog` shows a valid parser config.
- **`/kmp-forge-add-library`** resolves versions from `maven-metadata.xml` (numeric-only, version-sorted — it queried the frozen solrsearch index) and derives valid catalog keys (kebab-case alias + camelCase version key; the old key kept the dots).
- **CI actions off Node 20** (removed from runners 2026-09-23): checkout v7, setup-java v6, setup-gradle v6 (its caching is the proprietary `gradle-actions-caching` component — using it accepts Gradle's Terms of Use; pin `@v5` to opt out), upload-artifact v7, download-artifact v8, git-cliff-action v4, action-gh-release v3. CI's JDK is Zulu 21, matching kmp.new's `gradle-daemon-jvm.properties` (no per-run JDK download). `docs/observability.md` uses `getsentry/action-release@v3` and no longer passes R8 mappings as JS `sourcemaps`.
- **`docs/ci.md` pr.yml drift** — the fenced sample now matches `overlay/ci/pr.yml.tmpl` (split steps, bare `jvmTest`, `vars.IOS_ENABLED`).

## [0.3.2] - 2026-06-22

### Changed (BREAKING)
- **Target the current kmp.new output: Kotlin 2.4 / AGP 9 / Compose MP 1.11 / Gradle 9.1 and the `:shared` + app-module layout.** kmp.jetbrains.com now generates a `:shared` KMP library (the composition host — `App.kt`, `startKoin`, the Nav 3 back stack) plus thin `:androidApp`/`:desktopApp` (+ `iosApp/`) instead of a single `:composeApp`, and uses AGP 9's `com.android.kotlin.multiplatform.library` plugin. The overlay was reworked to match:
  - **Catalog** no longer re-pins the toolchain — build-logic plugin entries now reference kmp.new's own `kotlin`/`agp`/`composeMultiplatform`/`androidx-lifecycle`/`kotlinx-coroutines` keys, so the whole build shares one toolchain version (no "plugin loaded with different version" failure) and the overlay is drift-proof across future kmp.new bumps.
  - **build-logic is now a precompiled script plugin** (`build-logic/src/main/kotlin/kmp-forge.kmp.library.gradle.kts`) instead of a Kotlin class plugin: a class plugin can't compile against KGP 2.4 under Gradle 9.1's embedded Kotlin 2.2. The `ComposeApp` convention plugin (`kmp-forge.compose.app`) was removed — modules apply Compose via `alias(libs.plugins.composeMultiplatform/composeCompiler)` and the Android target via `alias(libs.plugins.androidMultiplatformLibrary)` + an `androidLibrary { namespace; compileSdk; minSdk; jvmTarget = 17 }` block.
  - **`:shared` is the composition root**; `:androidApp`/`:desktopApp`/`iosApp/` are thin entry points. Updated in lockstep: `docs/{architecture,stack,ci,secrets,observability,release,i18n-a11y,ios-troubleshooting}.md`, `kmp-{feature-builder,migrator,reviewer}`, `kmp-forge-{init,add-feature,add-screen,add-platform,doctor,adopt}`, ADRs 0002–0006, CI templates, `.gitignore`, `CLAUDE.md`, README, skills.

### Fixed
- **Kover** 0.9.1 → 0.9.8 — 0.9.1 rejected AGP 9's KMP library plugin (`Kover requires extension with name 'android'`).
- **`apply-overlay.sh patch-settings`** now ensures a trailing newline before appending `include(...)` lines (kmp.new's `settings.gradle.kts` ships without one, which produced `include(":shared")include(":ui")`).
- **`.editorconfig`** ktlint config for the locked stack: disabled `filename`, `multiline-expression-wrapping`, and `chain-method-continuation` (they fight idiomatic `val xModule = module {}` and the `libs.versions.x.get().toInt()` catalog idiom), and exempt `@Composable` from `function-naming`.
- **Detekt** now actually scans KMP `commonMain` (was `NO-SOURCE` / a vacuous gate) via `source.setFrom("src")` + the project `detekt.yml`; design-token files pass with `MagicNumber.ignorePropertyDeclaration` and `FunctionNaming.ignoreAnnotated: [Composable]`.
- **`:ui` module template** declares its `koin.core` dependency (`uiModule.kt` uses Koin).
- **Test tasks** set `failOnNoDiscoveredTests = false` so a utility-only `commonTest` (e.g. `TestDispatcherProvider`) doesn't fail the Gradle 9 build.
- **`navigation3-ui` now uses the JetBrains Compose Multiplatform port** — the locked stack pinned Google's `androidx.navigation3:navigation3-ui`, whose only KMP variants are `androidJvm`/`jvm`/`linux_x64`; sitting in `commonMain`, it cannot resolve for iOS/macOS/js/wasm targets, so any non-Android scaffold would fail to build. Switched the UI artifact to `org.jetbrains.androidx.navigation3:navigation3-ui` (full multiplatform) and dropped the pin `1.1.2 → 1.1.1` (the port's latest stable — `1.1.2` never existed for it). `navigation3-runtime` correctly stays on Google's `androidx.navigation3:navigation3-runtime`: that artifact *is* fully multiplatform and is exactly what the UI port depends on, so the shared `androidxNavigation3` ref still resolves both. `fetch-latest-versions.sh` now tracks the UI port on Maven Central (was Google Maven — the version-line mismatch behind the upstream bug report). Corrects the 0.3.1 note "`androidx.navigation3` correctly stays on Google Maven", which held only for the runtime, not the UI. Touched (lockstep): `overlay/gradle/libs.versions.toml.additions.tmpl`, `docs/stack.md`, ADR 0004, `scripts/fetch-latest-versions.sh`.

## [0.3.0] - 2026-06-01

### Changed (BREAKING)
- **Restrictive visibility + explicit state + Nav 3 entry contributions** — the locked stack is now deliberately restrictive about visibility, and the generated `:feature-*` contract changed:
  - **Visibility:** `private`/`internal` by default; `public` only for a module's deliberate cross-module API. In `:data`, repository implementations, data sources, DTOs, and `RealDispatcherProvider` are `internal`. A `:feature-*`'s only public API is its `Route`, Koin `Module`, and `addXEntries(...)`; `State`/`ViewModel`/`Screen` are `internal`, `Content` is `private`. Use-case constructors stay public so feature tests build them with fakes.
  - **No default values** on domain entities or presentation `State`; `State` carries a `companion object { val Initial }` (single starting-state source for `container(...)` and tests). DTOs may keep wire-format defaults.
  - **Nav 3 entry contributions:** the app no longer references feature screens via `NavDisplay { when }`. Each feature exposes a public `EntryProviderBuilder<NavKey>.addXEntries(...)` that contributes `entry<Route> { Screen(...) }`, composed by the app in `NavDisplay(entryProvider = entryProvider { ... })`. Cross-feature navigation flows through callbacks (the app owns target routes), so a feature never imports another feature's `Route`.
  - Migrate existing projects via `/kmp-forge-adopt`'s new `visibility` layer + updated `nav` layer. Touched (lockstep): `docs/{architecture,stack,testing}.md`, `kmp-reviewer`, `kmp-feature-builder`, `kmp-migrator`, all feature/domain/data templates (+ new `FeatureNavEntry.kt.tmpl`), `kmp-forge-{adopt,add-feature,add-screen}`, ADR 0004, `CLAUDE.md`.
- **Error handling now uses [kotlin-result](https://github.com/michaelbull/kotlin-result)** — `Result<T, DomainError>` is its two-param `Result<V, E>` (`Ok`/`Err`), Gradle coordinate `com.michael-bull.kotlin-result:kotlin-result` (+ `kotlin-result-coroutines`), import package `com.github.michaelbull.result.*`, declared `api` in `:domain`. Resolves the prior contradiction where ADR 0005 said stdlib `Result<T>` (single-param, `Throwable`-only) while every signature used the two-param form. Feature-state `error` slot is now typed `DomainError?` (was `String?`). Touched: catalog additions, `:domain` build, feature State/ViewModel templates, ADR 0005, `docs/{architecture,stack,testing,product-workflow}.md`, `kmp-reviewer`, `kmp-feature-builder`, `kmp-migrator`, `CLAUDE.md`.

### Added
- **`/kmp-forge-adopt` command + `kmp-migrator` agent** — bring the locked stack to an *existing* KMP project (no kmp.new download). Phase A applies the overlay non-destructively (additive merges auto; overwrite-danger files diffed and hand-merged); Phase B is a dependency-ordered, `kmp-reviewer`-audited refactor delegated to the new `kmp-migrator` agent, one locked-stack layer per invocation (dispatchers, result, repos, koin, orbit, nav, module-deps, visibility, tests, a11y).

### Changed
- **Self-contained marketplace** — collapsed the standalone `arthurnagy/claude-plugins` marketplace repo into this repo. `.claude-plugin/marketplace.json` now lives at the repo root with `source: "./"` (caveman-style). Install path is now `/plugin marketplace add arthurnagy/kmp-forge` + `/plugin install kmp-forge@kmp-forge`. Reason: the standalone marketplace was triggering an SSH clone of `arthurnagy/kmp-forge` regardless of source shape (`github`, `git`, `git-subdir` all failed in different ways); a single self-contained repo sidesteps the second-repo clone entirely.

### Fixed
- **State-only-events doc drift** (#3) — stopped recommending `postSideEffect` in docs that lingered after the v0.2 state-only switch.
- **Component review findings** (#4) — resolved inconsistencies flagged by a Claude Code component review pass across commands and agents.

## [0.1.0] - 2026-05-25

Initial release.

### Features
- `/kmp-forge-init` — end-to-end scaffold flow. Drives the JetBrains KMP Wizard at kmp.jetbrains.com via explicit step-by-step instructions (no URL params), then applies the overlay: CLAUDE.md, modules, CI, git, product docs, build-logic.
- `/kmp-forge-add-feature <name>` — generates a complete `:feature-<name>` module on the locked stack (Compose screen + Orbit ViewModel + state + Koin module + Nav 3 destination + commonTest skeleton), wired into composeApp Koin start + NavDisplay.
- `/kmp-forge-add-screen <feature> <screen>` — adds a screen inside an existing feature module.
- `/kmp-forge-add-platform <desktop|web|ios>` — extends an existing project to a new platform.
- `/kmp-forge-add-library <query>` — klibs.io lookup + `libs.versions.toml` insert.
- `/kmp-forge-bump-stack` — refreshes `libs.versions.toml` against latest stable versions of every locked-stack library.
- `/kmp-forge-spec [--from-dump]` — authors `docs/MVP_SPEC.md` (interactive interview or free-form paste).
- `/kmp-forge-doctor` — diagnostic for JDK / Xcode / Android SDK / Gradle / Kotlin / signing / git hooks.

### Agents
- `kmp-feature-builder` — multi-file feature scaffolder invoked by `/kmp-forge-add-feature`. Reads existing features for style reference, wires use cases from `:domain` when relevant, builds + reports.
- `kmp-reviewer` — diff/branch/file reviewer enforcing locked-stack conventions: Orbit MVI patterns, Koin DI, Nav 3 type-safe routes, Result+DomainError, DispatcherProvider injection, fakes-not-mocks in commonTest, a11y rules (contentDescription, touch target, no hardcoded sp), RTL convention (start/end not left/right), secrets in untracked files.

### Skills
- `conventional-commits` · `git-cliff-changelog` · `github-release-artifacts` · `mvp-spec-authoring` · `adr-authoring`

### Locked stack
- Kotlin Multiplatform + Compose Multiplatform · Orbit MVI · Koin · AndroidX Navigation 3 (1.1.2) · Coil 3 · Kermit · kotlinx-datetime · kotlinx-serialization · Compose Multiplatform Resources
- Opt-in: Ktor Client · SQLDelight · Sentry · Firebase App Distribution · gradle-play-publisher
- Excluded by default: image picker, fastlane, analytics, perf monitoring

### Architecture
- Hybrid: `:feature-<name>` = presentation only; shared `:domain` + `:data` + `:ui`; `build-logic/` convention plugins from day one.
- Error handling: `Result<T>` + sealed `DomainError` per use case. No exceptions across layer boundaries.
- Coroutines: `DispatcherProvider` interface injected; no raw `Dispatchers.*` references in `:domain`/`:data`/`:feature-*`.
- Testing: `kotlin.test` + Orbit `ContainerHost.test()` + Turbine for edge cases + Compose UI Test. Fakes preferred; MockK allowed only in `jvmTest`/`androidTest`.
