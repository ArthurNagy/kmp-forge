# i18n & accessibility

## Internationalization

### Setup

Compose Multiplatform Resources is the default. String tables live under `commonMain/composeResources/values-<locale>/strings.xml`.

```
shared/src/commonMain/composeResources/
├── values-en/strings.xml      ← default locale at scaffold
├── values-fr/strings.xml      ← add when localizing
└── values-es/strings.xml
```

Scaffold ships only `values-en/`. Add additional locales as needed — no per-locale boilerplate required (Compose MP Resources handles fallback automatically).

### Usage

```kotlin
@Composable
fun GalleryEmptyState() {
    Text(stringResource(Res.string.gallery_empty))
}
```

**Anti-pattern**: hardcoded user-facing strings. Every `Text(...)` argument and every `contentDescription` reads from `Res.string`.

Exception: error messages from `DomainError` resolve to string resources at the UI layer, not in `:domain`. `:domain` carries enum-like sealed types; `:feature-*` maps them to resources.

### Pluralization

```xml
<plurals name="photo_count">
    <item quantity="one">%d photo</item>
    <item quantity="other">%d photos</item>
</plurals>
```

```kotlin
Text(pluralStringResource(Res.plurals.photo_count, count, count))
```

### Number / date formatting

Use `kotlinx-datetime` + per-platform formatter for locale-aware date/time. For numbers, defer to platform formatters (`NSNumberFormatter` on iOS via `expect/actual`) when locale awareness matters.

## RTL (right-to-left)

Every scaffolded project is **RTL-ready** by default.

### Convention

Never use `Modifier.padding(left = ..., right = ...)`. Always:

```kotlin
Modifier.padding(start = 16.dp, end = 16.dp)
```

`start`/`end` flip automatically when the locale is RTL (Arabic, Hebrew, Farsi). `left`/`right` are absolute and break RTL layouts.

Same rule for:
- `Alignment.Start` / `Alignment.End` (not `Alignment.Left` / `Alignment.Right`)
- `Modifier.absoluteOffset()` (avoid; use plain `offset` which is direction-aware)
- `TextDirection.Content` (the default, picks based on text content)

### Testing RTL

```kotlin
@Test
fun `gallery screen mirrors in RTL`() = runComposeUiTest {
    setContent {
        CompositionLocalProvider(LocalLayoutDirection provides LayoutDirection.Rtl) {
            AppTheme { GalleryScreen(...) }
        }
    }
    // assert layout positions
}
```

Wrap in `LayoutDirection.Rtl` to validate mirroring.

The `kmp-reviewer` agent flags any new `left =` / `right =` modifiers.

## Accessibility

### Rules enforced

1. **`contentDescription` mandatory on `Icon` and `Image`**. Decorative icons use `contentDescription = null` (explicit, not omitted).

   ```kotlin
   // OK — meaningful icon
   Icon(Icons.Default.Search, contentDescription = stringResource(Res.string.search))
   // OK — decorative
   Icon(Icons.Default.ChevronRight, contentDescription = null)
   // ANTI-PATTERN — flagged by reviewer
   Icon(Icons.Default.Search, contentDescription = "search")  // hardcoded string
   ```

2. **Minimum touch target 48dp** (Material guideline). Use the design token:

   ```kotlin
   object AppDimens {
       val touchTargetMin = 48.dp
   }
   ```

   Custom clickable Composables must size at least `AppDimens.touchTargetMin`:

   ```kotlin
   Modifier.minimumInteractiveComponentSize()      // Compose Material built-in
   // OR
   Modifier.size(min = AppDimens.touchTargetMin)
   ```

3. **No hardcoded `.sp` font sizes**. Always read from `MaterialTheme.typography`:

   ```kotlin
   Text(text, style = MaterialTheme.typography.bodyLarge)        // OK
   Text(text, fontSize = 16.sp)                                  // ANTI-PATTERN
   ```

   Reason: dynamic type scaling depends on theme-relative sizing. Hardcoded sp ignores user font-size preferences.

### Other a11y conventions

- **`testTag`** on every interactive element that needs to be reachable in tests. Use a stable convention: `<screen>:<element>` (e.g. `gallery:photo:${id}`).
- **`Modifier.semantics { }`** for grouping (e.g. `mergeDescendants = true` on rows that should announce as one item).
- **Focus order** — default is reading order; override only when layout breaks expected traversal.
- **High contrast** — design tokens must clear WCAG AA contrast against background. Validate via Material Theme Builder or manual check.

### Enforcement

Two layers:

1. **detekt custom ruleset** (in `overlay/build-logic/`):
   - `IconWithoutContentDescription`
   - `HardcodedFontSize`
   - `AbsoluteLeftRightPadding`

   If custom rules turn out to be more work than they're worth, fall back to layer 2 only.

2. **`kmp-reviewer` agent** (always available) — flags the same patterns in PR diffs as backup, plus harder-to-rule patterns (missing `testTag`, `Modifier.absoluteOffset`, color hardcodes outside `:ui`).

## Dark mode

Default-on. `AppTheme` resolves color scheme via `isSystemInDarkTheme()` *unless* user has set a manual override stored in DataStore.

```kotlin
@Composable
fun AppTheme(content: @Composable () -> Unit) {
    val override by themePreferences.modeFlow.collectAsState(initial = ThemeMode.SYSTEM)
    val isDark = when (override) {
        ThemeMode.LIGHT -> false
        ThemeMode.DARK -> true
        ThemeMode.SYSTEM -> isSystemInDarkTheme()
    }
    MaterialTheme(
        colorScheme = if (isDark) DarkScheme else LightScheme,
        typography = AppType.material,
        content = content,
    )
}
```

Settings UI exposes a tri-state toggle (Light / Dark / System) writing to DataStore.

Both light and dark color schemes ship populated in `:ui`. Generate via [Material Theme Builder](https://material-foundation.github.io/material-theme-builder/) and paste into `LightScheme.kt` / `DarkScheme.kt`.
