# 2. Use Koin for dependency injection

Date: ${SCAFFOLD_DATE}
Status: Accepted

## Context

We need a DI container that works in `commonMain` so ViewModels, repositories, and use cases can be wired without per-platform DI code.

Alternatives considered:
- **Hilt** — Android-only. Cannot live in `commonMain`. Rules out for KMP.
- **kotlin-inject** — compile-time DI, type-safe, KMP-supported. More ceremony, slower iteration during early development.
- **Metro (zacsweers/metro)** — newer compile-time KMP DI based on KSP, Anvil-style. Less mature.

## Decision

Use [Koin](https://insert-koin.io/) with `koin-core`, `koin-compose`, and `koin-compose-viewmodel`. Each module defines a `<moduleName>Module: Module`. The composition root in `:shared` calls `startKoin { modules(...) }` once inside `App.kt`, so every platform entry point (`:androidApp`, `:desktopApp`, `iosApp/`) gets DI wired by simply hosting `App()`.

## Consequences

- Easier: pure-Kotlin, KMP-native, low ceremony, fast iteration, easy to swap impls in tests.
- Harder: runtime resolution (no compile-time graph check). Reviewer enforces no `GlobalContext.get()` calls; ViewModels and repos always inject via constructor.
- Tests use `KoinTestRule` or direct construction with fakes — fakes preferred (see [testing.md](https://github.com/arthurnagy/kmp-forge/blob/main/docs/testing.md)).
